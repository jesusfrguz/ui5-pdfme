Generación PDF diferida

Encola un documento, permite que el usuario continúe trabajando y genera el PDF de forma fiable en un worker Node.js con plantillas versionadas.

Objetivo

Separar solicitud y renderizado

Fiori / ABAP→Job QUEUED→Worker Node→PDF→Object Store / DMS

El diseñador continúa en UI5/JavaScript/React. El backend recupera una versión publicada, carga los datos empresariales, ejecuta MappingEngine y llama a generatePdf sin interfaz. El navegador no necesita permanecer abierto.

REST

Contrato de jobs

POST /api/pdf-jobs
Idempotency-Key: sales-order-5001-v3
Content-Type: application/json

{
  "templateId": "sales-order",
  "filename": "order-5001.pdf",
  "runAt": "2026-08-27T02:00:00Z",
  "payload": { "data": { "order": { "number": "5001" } } }
}

La respuesta es 202 Accepted con id, statusUrl y contentUrl. Consulta el estado hasta DONE o FAILED. La descarga devuelve 409 mientras el PDF no esté listo.

Producción SAP: envía preferentemente businessObject y businessKey. El worker debe resolver los datos mediante una Destination autorizada; evita persistir documentos empresariales completos dentro de la cola.
Servidor

Instalación Node.js pura

cd examples/deferred/node
npm install
npm start

Sin DATABASE_URL usa memoria. Con PostgreSQL crea las tablas de referencia y emplea FOR UPDATE SKIP LOCKED, por lo que pueden ejecutarse varios workers sin procesar el mismo job.

DATABASE_URL=postgresql://pdfme:secret@localhost:5432/pdfme
PDF_OUTPUT_DIR=/srv/pdfme/output
API_TOKEN=replace-me
WORKER_ENABLED=true
npm start

Las variables adicionales controlan host, puerto, CORS, tamaño máximo, intervalo de polling y número de intentos. Se puede separar API y worker iniciando una instancia con WORKER_ENABLED=false.

Despliegue portable

Docker y Docker Compose

Docker empaqueta la API y el worker de generación diferida. Es una opción de despliegue de este patrón; el editor no lo necesita y el mismo worker también puede ejecutarse directamente con Node o CAP.

La imagen de ejemplo se ejecuta sin privilegios de root, publica el puerto 3001, expone la comprobación /health y conserva los PDF generados en un volumen.

Prueba local en memoria

Inicia el servicio con la cola y las plantillas en memoria. Este modo pierde el estado al reiniciar y no debe escalarse.

cd examples/deferred/docker
docker compose up --build

PostgreSQL persistente

Añade una base de datos y volúmenes duraderos para plantillas, trabajos y PDF. Es el modo adecuado para réplicas y despliegues reales.

docker compose -f compose.yaml -f compose.postgres.yaml up --build
Antes de exponer el servicio: copia .env.example a .env, sustituye API_TOKEN y POSTGRES_PASSWORD, limita CORS_ORIGIN y usa OAuth/XSUAA, mTLS o un gateway en producción.

Abrir el Dockerfile y las configuraciones Compose en GitHub.

SAP

CAP Node.js y SAP BTP

cd examples/deferred/cap
npm install
npm run watch

El servicio OData V4 está en /odata/v4/pdf-generation. La acción enqueue crea el job y publica RenderRequested en la cola persistente de CAP. Si se proporciona runAt, usa la planificación de la misma cola.

npx cds add hana
npx cds add xsuaa
npx cds add mta
npx cds build --production
mbt build
cf deploy mta_archives/*.mtar

Asigna PdfViewer, PdfGenerator y TemplateEditor a colecciones de roles. El ejemplo guarda el binario en la base de datos para ser autocontenido; para PDFs grandes utiliza Object Store o Document Management y conserva únicamente la clave y metadatos.

Cliente UI5

Consumir desde Fiori

La vía REST recomendada publica el renderer tras un approuter y una Destination. Fiori envía el job, libera el busy indicator al recibir 202 y muestra el proceso en una lista de trabajos.

const response = await fetch("/pdf-api/api/pdf-jobs", {
  method: "POST",
  headers: {
    "content-type": "application/json",
    "idempotency-key": `order-${order.SalesOrder}`
  },
  body: JSON.stringify({
    templateId: "sales-order",
    filename: `order-${order.SalesOrder}.pdf`,
    payload: { data: { order } }
  })
});
const job = await response.json();

Para CAP, crea un modelo OData V4 y llama a /enqueue(...) mediante bindContext. Después lee /Jobs(<uuid>). El manual técnico incluye el código completo de envío, polling y descarga.

ECC / S/4HANA

Consumir desde ABAP

  1. Crea una Destination HTTP SM59 o Communication Arrangement.
  2. Haz POST del job con una clave de idempotencia estable.
  3. Guarda el ID junto al objeto de negocio.
  4. Un job de fondo ABAP consulta el estado; no mantengas un proceso de diálogo esperando.
  5. Al finalizar, descarga el xstring y archívalo mediante ArchiveLink, DMS/GOS o el repositorio aprobado.

Producción

Seguridad y operación

  • Solo plantillas publicadas, versionadas y autorizadas.
  • Nunca ejecutes URLs, loaders, formatters o plugins recibidos del job.
  • El renderer de referencia rechaza URLs remotas en basePdf.
  • Usa XSUAA/OAuth2 o mTLS; el token estático es solo una ayuda de despliegue aislado.
  • Aísla tenant/propietario y limita payload, inputs, imágenes, tiempo, intentos y retención.
  • Monitoriza antigüedad de cola, fallos, tiempo, tamaño, dead letters y capacidad.
