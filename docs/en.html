Functional

What it solves

It lets users visually build invoices, orders, labels, certificates, or any print form, then lets the application fill the design with real data without coupling it to the backend.

Visual design

Text, tables, lists, images, signatures, SVG, shapes, dates, selectors, and barcodes.

Combined data

JSON, REST, functions, OData V2/V4, and UI5 models with dependencies and fallback values.

Real output

A versionable template, PDF preview, download, print, and bytes that the application can reuse.

Quick start

Install the package and choose an adapter. All three use the same template, data-source, and mapping contract.

# Once published on npm
npm install ui5-pdfme

# Current precompiled release, including the UI5 distribution
npm install https://github.com/jesusfrguz/ui5-pdfme/releases/download/v0.1.0/ui5-pdfme-0.1.0.tgz

JavaScript

import { WebPdfTemplateStudio } from "ui5-pdfme";

const studio = new WebPdfTemplateStudio("#studio", {
  template,
  dataSources: [{ id: "order", type: "rest", url: "/api/orders/5001" }],
  mapping: { fields: { customer: "order.customerName" } },
  language: "en",
  filename: "order.pdf"
});

Technical

Architecture

JSON / REST / OData / function→DataResolver→MappingEngine→pdfme→PDF

DataResolver fetches independent sources in parallel and respects dependsOn. MappingEngine converts declarative paths into pdfme inputs. The adapters only manage lifecycle, events, and presentation.

Integration

Data and OData

const dataSources = [
  { id: "order", type: "rest", url: "/api/orders/5001" },
  { id: "brand", type: "json", data: { company: "Example Inc." } },
  { id: "totals", type: "function", loader: "totals", dependsOn: ["order"] },
  { id: "products", type: "odata", url: "/odata/v4/Products?$top=50" }
];

On the web, OData uses HTTP and normalizes V2 (d.results) and V4 (value) responses. In UI5, prefer the odata provider with modelName and path; this preserves destinations, batch, authentication, and CSRF handling from the application model.

Dependencies: a calculated source can read context.data.order when it declares dependsOn: ["order"]. Cycles are rejected.
studio.registerLoader("totals", (_source, context) => ({
  total: context.data.order.items.reduce((sum, item) => sum + item.amount, 0)
}));
Declarative

Mappings and formats

const mapping = {
  fields: {
    customer: "order.customer.name",
    reference: { path: "order.reference", defaultValue: "—" },
    header: { template: "Order {order.number} · {brand.company}" },
    total: { path: "totals.total", formatter: "number",
      options: { locale: "en-US", style: "currency", currency: "USD" } },
    items: { path: "order.items", formatter: "table",
      options: { columns: ["description", "quantity", "amount"] } }
  }
};

Built-in formatters: raw, json, join, number, date, and table. Custom formatters are registered by name and must be deterministic.

Design

Templates

A pdfme template contains its background/size and an array of schemas per page. Each schema's name is the stable key used by the mapping.

const template = {
  basePdf: { width: 210, height: 297, padding: [12, 12, 12, 12] },
  schemas: [[
    { name: "title", type: "text", position: { x: 20, y: 18 },
      width: 90, height: 12, content: "INVOICE", fontSize: 22 },
    { name: "customer", type: "text", position: { x: 20, y: 42 },
      width: 130, height: 10, content: "Customer" }
  ]]
};

The data panel lets users insert fields and tables from resolved samples. In production, save the template together with its mapping, contract version, language, author, status, and date.

Operations

Persistence and lifecycle

The package does not impose a database. The application can persist data in OData, REST, CAP, ABAP, BTP, or its own storage. A recommended entity includes: ID, version, name, document type, template JSON, mapping JSON, data-contract version, draft/published status, author, and timestamps.

Publishing must be an authorized operation. Keep immutable versions so that a historical reprint uses exactly the approved design.
Production

Security

  • Do not store tokens, cookies, or credentials in a template or source.
  • Restrict the origins, paths, and collection sizes allowed by the backend.
  • Field visibility is not a replacement for service authorization.
  • Treat remote text as untrusted; previews use text APIs.
  • Validate and version the template/mapping before publishing.
  • Standard browsers do not allow silent printing; it requires controlled infrastructure.
