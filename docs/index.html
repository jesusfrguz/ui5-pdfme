Funcional

Qué resuelve

Permite crear visualmente plantillas para cualquier documento PDF —como facturas, pedidos, etiquetas, certificados o formularios— y rellenarlas automáticamente con datos reales procedentes de distintas fuentes. La generación puede realizarse de forma eficiente y en tiempo real directamente en el navegador, o de manera diferida.

Diseño visual

Textos, tablas, listas, imágenes, firmas, SVG, formas, fechas, selectores y códigos de barras.

Datos combinados

JSON, REST, funciones, OData V2/V4 y modelos UI5 con dependencias y valores alternativos.

Salida real

Plantilla versionable, vista previa PDF, descarga, impresión y bytes reutilizables por la aplicación.

CapacidadResultado
VariablesUn campo del esquema recibe un valor por ruta o plantilla de texto.
Tablas dinámicasUna colección se transforma en la matriz JSON que espera pdfme.
Varios documentosmapping.repeat genera un input por registro.
ExtensiónProveedores, loaders, formatters y plugins de esquema registrables.
Mapa de conceptos

Qué guía necesitas

Hay tres decisiones principales: integrar el motor, persistir las plantillas y, solo si el proceso lo necesita, generar en segundo plano. SAP/OData pertenece a la decisión de repositorios: es una forma de implementar ese catálogo.

Técnico

Arquitectura

JSON / REST / OData / función→DataResolver→MappingEngine→pdfme→PDF

DataResolver obtiene fuentes independientes en paralelo y respeta dependsOn. MappingEngine convierte rutas declarativas a inputs de pdfme. Los adaptadores solo gestionan lifecycle, eventos y presentación.

Integración

Datos y OData

const dataSources = [
  { id: "order", type: "rest", url: "/api/orders/5001" },
  { id: "brand", type: "json", data: { company: "Example S.L." } },
  { id: "totals", type: "function", loader: "totals", dependsOn: ["order"] },
  { id: "products", type: "odata", url: "/odata/v4/Products?$top=50" }
];

En web, OData usa HTTP y normaliza respuestas V2 (d.results) y V4 (value). En UI5, usa preferentemente el proveedor odata con modelName y path; así conserva destinos, batch, autenticación y CSRF del modelo de la aplicación.

Dependencias: una fuente calculada puede leer context.data.order si declara dependsOn: ["order"]. Los ciclos se rechazan.
studio.registerLoader("totals", (_source, context) => ({
  total: context.data.order.items.reduce((sum, item) => sum + item.amount, 0)
}));
Declarativo

Mapeos y formatos

const mapping = {
  fields: {
    customer: "order.customer.name",
    reference: { path: "order.reference", defaultValue: "—" },
    header: { template: "Pedido {order.number} · {brand.company}" },
    total: { path: "totals.total", formatter: "number",
      options: { locale: "es-ES", style: "currency", currency: "EUR" } },
    items: { path: "order.items", formatter: "table",
      options: { columns: ["description", "quantity", "amount"] } }
  }
};

Formatters incluidos: raw, json, join, number, date y table. Los custom formatters se registran por nombre y deben ser deterministas.

Diseño

Plantillas

Una plantilla es la definición reutilizable del documento: describe las páginas y la posición, tamaño y estilo de cada elemento. Los datos de una factura, pedido o etiqueta no se guardan dentro del diseño; llegan por separado y el mapeo decide qué valor ocupa cada campo.

Anatomía de una plantilla

ParteResponsabilidad y ejemplo
basePdfDefine el tamaño, los márgenes y el fondo; por ejemplo, A4 de 210 × 297 mm con 12 mm de margen. Puede ser una página en blanco o un PDF importado.
schemasContiene un array por página y, dentro de cada uno, los campos que se dibujarán. La primera posición representa la página 1.
SchemaDescribe un campo —por ejemplo un texto, una tabla, una imagen o un código QR— mediante su identificador, tipo, posición, dimensiones, contenido inicial y estilo.
mapping.fieldsConecta el name del schema con una ruta de datos, una plantilla de texto o un formatter registrado; por ejemplo, customer: "order.customer".
Contrato principal: el name de cada schema debe ser único y estable en todas las páginas. Es la clave que une el diseño con mapping.fields; no uses como identificador una etiqueta traducida que pueda cambiar.

Ejemplo: factura con texto, tabla y pie repetido

const template = {
  basePdf: { width: 210, height: 297, padding: [12, 12, 25, 12] },
  schemas: [[
    { name: "title", type: "text", position: { x: 20, y: 18 },
      width: 90, height: 12, content: "FACTURA", readOnly: true,
      fontSize: 22 },
    { name: "customer", type: "text", position: { x: 20, y: 42 },
      width: 130, height: 10, content: "Cliente",
      showLabel: true, label: "Cliente" },
    { name: "items", type: "table", position: { x: 20, y: 68 },
      width: 170, height: 70, content: "[]",
      head: ["Concepto", "Cantidad", "Precio"] },
    { name: "total", type: "text", position: { x: 120, y: 150 },
      width: 70, height: 10, content: "0,00 €",
      showLabel: true, label: "Total", alignment: "right" },
    { name: "footer", type: "text", position: { x: 20, y: 278 },
      width: 170, height: 6,
      content: "Página {currentPage} de {totalPages}",
      readOnly: true, fixedPosition: true,
      repeatOnEveryPage: true, alignment: "center" }
  ]]
};

const mapping = {
  fields: {
    customer: "order.customer",
    items: {
      path: "order.items",
      formatter: "table",
      options: { columns: ["description", "quantity", "price"] }
    },
    total: {
      path: "order.total",
      formatter: "number",
      options: { locale: "es-ES", style: "currency", currency: "EUR" }
    }
  }
};

Con datos como { order: { customer: "Acme S.L.", items: [...], total: 1234.5 } }, el título y el pie permanecen estáticos, mientras que customer, items y total se resuelven para cada PDF. El formatter table transforma la colección en filas y number produce, por ejemplo, 1234,50 € según la configuración regional.

Campos estáticos y campos conectados

TipoDefinición y uso
EstáticoConserva su content y no tiene entrada en mapping.fields. Úsalo para títulos, instrucciones, logotipos y textos legales.
ConectadoSu name aparece en mapping.fields. El diseñador muestra Valor desde datos y permite elegir una ruta disponible. Úsalo para cliente, fecha, importe, dirección o cualquier valor que cambie.
ColecciónUsa un schema de tabla y el formatter table con el orden explícito de sus columnas. Es adecuado para líneas de pedido, movimientos o listados.
Fijo y repetidoActiva fixedPosition y, opcionalmente, repeatOnEveryPage. Es útil para cabeceras, pies y datos Text que deben conservar su posición; los textos estáticos repetidos admiten {currentPage} y {totalPages}.

Tres formas de empezar

Plantilla en blanco

Crea una página A4 vacía. Es la opción más sencilla cuando el documento nace en el diseñador.

Cargar PDF

Convierte todas las páginas de un PDF local en el fondo del diseño y permite colocar campos encima. El archivo debe ser un PDF válido.

Abrir del catálogo

Recupera una plantilla guardada. La búsqueda incluye nombre, descripción y etiquetas; también puedes filtrar por estado y repositorio.

El panel de datos permite insertar campos y tablas a partir de muestras resueltas. Los campos añadidos desde la paleta empiezan como estáticos; los insertados desde el panel de datos quedan conectados automáticamente. Antes de guardar, genera una vista previa con valores vacíos, textos largos y tablas con pocas y muchas filas.

Guardar, localizar y versionar

await studio.saveTemplateRecord({
  name: "Factura de venta · España",
  description: "Factura A4 en español con IVA y pie legal",
  tags: ["ventas", "factura", "es"],
  status: "draft",
  version: "3",
  metadata: { dataContractVersion: "2", language: "es" }
});

const published = await studio.listTemplates({
  search: "factura",
  status: "published"
});

await studio.loadTemplate("invoice-es-v3", {
  repositoryId: "backend"
});

La primera guardada solicita los metadatos; las siguientes actualizan el registro activo. En producción, guarda juntos la plantilla y su mapeo, y registra además versión del contrato de datos, idioma, autor, estado y fecha. Trata una versión publicada como inmutable: crea otra versión para modificarla y conserva la anterior para reimpresiones históricas.

Seguridad: no incluyas credenciales, cookies, tokens ni payloads privados en una plantilla. Las fuentes de datos almacenadas se excluyen de forma predeterminada y su aplicación requiere una configuración explícita.

Consulta el flujo visual en la guía de uso y la configuración de memoria, localStorage, REST, OData o funciones en la guía Catálogo y repositorios de plantillas.

Referencia

API y eventos

La instancia del estudio coordina cuatro operaciones: resolver datos, convertirlos en inputs de pdfme, editar o persistir la plantilla y producir el PDF. JavaScript y React usan WebPdfTemplateStudio; el control UI5 ofrece los mismos conceptos mediante métodos y eventos nativos.

Ciclo recomendado

const studio = new WebPdfTemplateStudio("#studio", {
  template,
  dataSources,
  mapping,
  autoResolve: false,
  filename: "factura-5001.pdf"
});

// Registra extensiones antes de resolver las fuentes que las utilizan.
studio
  .registerLoader("totals", totalsLoader)
  .registerFormatter("vat", vatFormatter);

const data = await studio.refreshData(); // Datos agrupados por id de fuente.
const inputs = studio.getInputs();       // Un objeto por PDF/documento.
const bytes = await studio.generate();   // Uint8Array con el PDF final.

console.info(data.order, inputs.length, bytes.byteLength);
studio.destroy(); // Al desmontar una integración JavaScript sin framework.

generate() resuelve los datos automáticamente si todavía no existen inputs. En procesos controlados suele ser preferible llamar antes a refreshData(): así puedes inspeccionar o validar data e inputs antes de generar. Las promesas rechazan con el error original; escucha también pdfme:error para observabilidad, pero conserva try/catch donde la aplicación deba recuperarse.

Escuchar eventos en JavaScript y React

En JavaScript, los eventos son CustomEvent despachados sobre el elemento raíz y su payload está en event.detail. La misma información puede recibirse con callbacks de configuración onNombreDelEvento; React utiliza estos callbacks y una ref para llamar a la API imperativa.

const host = document.querySelector("#studio");

host.addEventListener("pdfme:dataResolved", ({ detail }) => {
  console.info("Documentos preparados", detail.inputs.length);
});

host.addEventListener("pdfme:generated", ({ detail }) => {
  console.info("PDF generado", detail.bytes.byteLength, detail.blob.type);
});

host.addEventListener("pdfme:error", ({ detail }) => {
  reportError(detail.operation, detail.error);
});

// Alternativa válida en JavaScript y como props del adaptador React:
studio.configure({
  onTemplateSaved: ({ record }) => console.info(record.id),
  onError: ({ operation, error }) => reportError(operation, error)
});

Escuchar eventos en UI5

UI5 no usa event.detail: registra el handler con attach<Evento> o en la vista XML y lee cada valor con getParameter().

const studio = this.byId("printStudio");

studio.attachDataResolved((event) => {
  const inputs = event.getParameter("inputs");
  MessageToast.show(`${inputs.length} documento(s) preparado(s)`);
});

studio.attachGenerated((event) => {
  const blob = event.getParameter("blob");
  console.info("PDF", blob.size, blob.type);
});

studio.attachError((event) => {
  const operation = event.getParameter("operation");
  const error = event.getParameter("error");
  this.handlePdfError(operation, error);
});

Resumen en esta página

Repositorios de plantillas

Un repositorio persiste definiciones reutilizables de plantilla; no es la cola de generación ni el almacén de los PDF producidos. El catálogo visual permite buscar esas definiciones y abrirlas en el editor.

Los adaptadores incluidos son memory, localStorage, rest, odata y function.

templateRepositories: [{
  id: "browser",
  type: "localStorage",
  storageKey: "my-app.templates"
}, {
  id: "backend",
  type: "rest",
  url: "/api/templates"
}]

En Web, REST usa GET de colección/detalle y POST/PUT. OData V4 usa POST/PATCH; al indicar odataVersion: 2, el proveedor cambia filtros, count y actualización a la semántica V2. Ambos siguen enlaces de paginación hasta maxPages. En Fiori se puede indicar modelName y path para conservar destinos, batch y CSRF. Se incluyen ejemplos para Node, PostgreSQL y CAP/OData.

Abrir la guía completa de catálogo y repositorios. Si el repositorio será OData sobre SAP, usa además el selector RAP/CAP/CDS/SEGW.

Publicar debe ser una operación autorizada. Mantén versiones inmutables para que una reimpresión histórica use exactamente el diseño aprobado.
Producción

Seguridad

  • No guardes tokens, cookies o credenciales en una plantilla o fuente.
  • Limita orígenes, rutas y tamaño de colecciones permitidos por el backend.
  • La visibilidad de un campo no sustituye la autorización del servicio.
  • Trata textos remotos como no confiables; las vistas previas usan APIs de texto.
  • Valida y versiona template/mapping antes de publicar.
  • La impresión silenciosa no está permitida por navegadores estándar; requiere infraestructura controlada.
