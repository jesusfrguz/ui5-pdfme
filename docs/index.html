Funcional

Qué resuelve

Permite que un usuario construya visualmente facturas, pedidos, etiquetas, certificados o cualquier formulario de impresión y que la aplicación rellene el diseño con datos reales sin acoplarlo al backend.

Diseño visual

Textos, tablas, listas, imágenes, firmas, SVG, formas, fechas, selectores y códigos de barras.

Datos combinados

JSON, REST, funciones, OData V2/V4 y modelos UI5 con dependencias y valores alternativos.

Salida real

Plantilla versionable, vista previa PDF, descarga, impresión y bytes reutilizables por la aplicación.

Inicio rápido

Instala el paquete y escoge el adaptador. Los tres consumen el mismo contrato de plantilla, fuentes y mapeo.

# Cuando esté publicado en npm
npm install ui5-pdfme

# Release precompilada actual, incluida la distribución UI5
npm install https://github.com/jesusfrguz/ui5-pdfme/releases/download/v0.1.0/ui5-pdfme-0.1.0.tgz

Técnico

Arquitectura

JSON / REST / OData / función→DataResolver→MappingEngine→pdfme→PDF

DataResolver obtiene fuentes independientes en paralelo y respeta dependsOn. MappingEngine convierte rutas declarativas a inputs de pdfme. Los adaptadores solo gestionan lifecycle, eventos y presentación.

Integración

Datos y OData

const dataSources = [
  { id: "order", type: "rest", url: "/api/orders/5001" },
  { id: "brand", type: "json", data: { company: "Example S.L." } },
  { id: "totals", type: "function", loader: "totals", dependsOn: ["order"] },
  { id: "products", type: "odata", url: "/odata/v4/Products?$top=50" }
];

En web, OData usa HTTP y normaliza respuestas V2 (d.results) y V4 (value). En UI5, usa preferentemente el proveedor odata con modelName y path; así conserva destinos, batch, autenticación y CSRF del modelo de la aplicación.

Dependencias: una fuente calculada puede leer context.data.order si declara dependsOn: ["order"]. Los ciclos se rechazan.
studio.registerLoader("totals", (_source, context) => ({
  total: context.data.order.items.reduce((sum, item) => sum + item.amount, 0)
}));
Declarativo

Mapeos y formatos

const mapping = {
  fields: {
    customer: "order.customer.name",
    reference: { path: "order.reference", defaultValue: "—" },
    header: { template: "Pedido {order.number} · {brand.company}" },
    total: { path: "totals.total", formatter: "number",
      options: { locale: "es-ES", style: "currency", currency: "EUR" } },
    items: { path: "order.items", formatter: "table",
      options: { columns: ["description", "quantity", "amount"] } }
  }
};

Formatters incluidos: raw, json, join, number, date y table. Los custom formatters se registran por nombre y deben ser deterministas.

Diseño

Plantillas

Una plantilla pdfme contiene el fondo/tamaño y un array de esquemas por página. El name de cada esquema es la clave estable que utiliza el mapeo.

const template = {
  basePdf: { width: 210, height: 297, padding: [12, 12, 12, 12] },
  schemas: [[
    { name: "title", type: "text", position: { x: 20, y: 18 },
      width: 90, height: 12, content: "FACTURA", fontSize: 22 },
    { name: "customer", type: "text", position: { x: 20, y: 42 },
      width: 130, height: 10, content: "Cliente" }
  ]]
};

El panel de datos permite insertar campos y tablas a partir de muestras resueltas. Para producción, guarda la plantilla junto al mapeo, versión del contrato, idioma, autor, estado y fecha.

Operación

Persistencia y ciclo de vida

El paquete no impone base de datos. La aplicación puede persistir en OData, REST, CAP, ABAP, BTP o almacenamiento propio. Una entidad recomendada incluye: ID, versión, nombre, tipo de documento, template JSON, mapping JSON, versión del contrato de datos, estado borrador/publicado, autor y timestamps.

Publicar debe ser una operación autorizada. Mantén versiones inmutables para que una reimpresión histórica use exactamente el diseño aprobado.
Producción

Seguridad

  • No guardes tokens, cookies o credenciales en una plantilla o fuente.
  • Limita orígenes, rutas y tamaño de colecciones permitidos por el backend.
  • La visibilidad de un campo no sustituye la autorización del servicio.
  • Trata textos remotos como no confiables; las vistas previas usan APIs de texto.
  • Valida y versiona template/mapping antes de publicar.
  • La impresión silenciosa no está permitida por navegadores estándar; requiere infraestructura controlada.

Problemas comunes

SíntomaComprobación
Panel sin datosRegistra loaders antes de refreshData; revisa IDs y dependsOn.
Campo vacíoEl nombre del esquema debe coincidir con la clave en mapping.fields.
OData devuelve objeto inesperadoDistingue entidad/colección y verifica V2 d.results o V4 value.
WASM no encontradoUsa un bundler moderno y conserva URLs de assets/base path.
UI5 no carga la libreríaDeclara ui5.pdfme en el manifest y comprueba el grafo npm/UI5.
Tabla desbordaPrueba datasets grandes y usa una base flexible con márgenes adecuados.
